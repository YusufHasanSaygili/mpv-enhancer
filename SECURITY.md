# Security Policy

## Supported versions

Security fixes are applied to the latest published pre-release (`v0.1.1`) and
the current `main` branch. Pre-release versions may change quickly; upgrading
to the newest release is the supported remediation path.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's
[private vulnerability reporting](https://github.com/YusufHasanSaygili/mpv-enhancer/security/advisories/new)
form instead. Include a concise impact description, reproducible steps using
synthetic data, and the affected version.

Remove secrets, personal paths, private media, playlists, logs, and unrelated
system information before submitting a report. If a path is necessary to
explain the issue, replace identifying components with placeholders.

The maintainer will acknowledge a complete report when practical, investigate
it privately, and coordinate disclosure after a fix or mitigation is ready.
Please do not disclose the issue publicly before that coordination is complete.
